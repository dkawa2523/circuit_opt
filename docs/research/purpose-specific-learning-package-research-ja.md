# 回路計算基盤と併用する機械学習の追加効果と別パッケージ設計

本書は研究用途と採否条件の検討資料である。実装済み機能とモデリング方法は[統合マニュアル](../manual-ja.md)を参照する。

調査日: 2026年10月4日。対象は現行PCDの実装・入力契約と、機械学習・統計推定・プラズマ計測の一次資料である。旧MLのコード、実験履歴、旧MLを前提とする計画、git履歴は参照していない。本書のパッケージ名、API、データスキーマ、導入順序は新規の設計提案であり、実装済み機能とは区別する。

**現在の推奨は[回路計算と通常の最適化を超えるML研究用途の再検討](high-value-learning-methods-survey-ja.md)へ更新した。** 普通の回帰で扱える用途を高優先とした以下の順位、および汎用回帰パッケージを初期設計とする提案は撤回する。本書は現行PCDの契約と既往の技術調査の参考資料として残し、実装の採用順には使わない。

半導体製造プラズマとしての現在の研究仮説は「チャンバーごとの必要な素子部・接続、未知構成則、値と内部波形を同時推定し、識別できる範囲を評価したうえで外部回路と駆動を変えても再利用できるか」に絞る。履歴NN、構造・値の同定、回路連成には先行研究があり、その組合せだけでは技術的新規性を主張できない。「未学習仕様への構造設計知識の転移」は回路ML側の参考へ下げ、主題から外す。現行の静的AC・既知式・少数topologyだけでMLを必須とする根拠はなく、本PCDでの優位性と重要論文としての新規性は未実証である。

優先度は用途の有用性ではなく、**直接計算・通常の同定・簡単な統計手法に対し、MLがどの情報を追加し、何を改善できるか**で決める。感度に基づく実験計画、単純なKalman/RLS追従、有界RLC同定、少数の既知回路比較は有用でも、ML独自の追加効果は小さいため低優先とする。不確かさの提供も、それだけを独立した高優先用途にはしない。

実測データの提供・モデル学習・新規ベンチマークは本調査には含まれない。従って、個別装置での予測精度や速度向上は未確認である。以下の優先度は、現行コードと「回路計算自体は比較的安い」という利用条件からの設計判断である。

最新の用途選定、一次研究の実証範囲、最小入出力、採否条件は[研究用途の再検討](high-value-learning-methods-survey-ja.md)に記載する。2026年10月5日の再検討で、小NN・自由な履歴状態・4候補を先決めする案は撤回した。同書の第0.2節を優先し、既存の物理モデルが条件変更で成立しない原因を一箇所へ絞り、必要性が示された未知構成項だけを学習対象にする。

## 0 参考: 初回調査の用途分類（現在の推奨順位ではない）

### 0.1 優先する四つの内容

以下の順位は追加効果の期待値による設計判断である。データを準備しやすい順とは区別する。製品計測がなければ第1位の学習は成立せず、校正済み電気履歴だけがある場合は第2位から着手する。

| 順位 | 優先する学習内容 | 回路計算だけで足りない情報 | 期待する効果と成立条件 |
|---|---|---|---|
| 1 | **工程品質と実際の処理結果の予測** | 端子電気量からetch rate、膜厚、面内分布、CDなどへ至る装置・材料・化学・表面状態の関係 | 遅い・高価・疎な製品計測を補う。工程センサー、レシピ、材料、実計測ラベルが必要 |
| 2 | **未測定負荷と履歴依存挙動の予測** | 圧力、ガス、励振、温度、チャンバー状態、pulse履歴が端子負荷をどう変えるか | 将来または測定していない条件のR/X・有効パラメータ・負荷遷移を予測し、計算可能な運転範囲を広げる。実系列と同期条件が必要 |
| 3 | **複数センサーを使う早期異常・劣化予測** | 正常レシピ差を含む多数信号の組合せと、故障・品質悪化に先行するパターン | 誤警報を抑えながら検出を早める。管理図・残差・線形状態推定では取り切れない情報がある場合に高効果 |
| 4 | **学習した工程応答に基づく計測・実験の削減** | 次に実測すべき製品、条件、レシピの価値を決める未確定の実機応答 | 第1〜3位の予測と不確かさを使い、高価な実測を必要な箇所へ配分する。固定sampling・通常DOEに対する実測削減を確認する |

第4位は第1〜3位のモデルを活用する段階であり、独立した大規模学習器を最初に作る理由ではない。回路パラメータを識別するために周波数を選ぶだけなら、安い回路計算の感度を使う通常の実験計画を優先する。

第1位には工業用plasma etchでの仮想計測の実証があるが、その研究の順位や精度が本装置でも成立するとは限らない。[plasma etchの実証研究](https://mural.maynoothuniversity.ie/id/eprint/3560/1/JR_Global.pdf) 第4位にはCMPデータによるonline GPと動的計測の研究があり、これはプラズマ用途への適用可能性を検討する参考である。[NISTの動的計測研究](https://www.nist.gov/publications/comparative-study-semiconductor-virtual-metrology-methods-and-novel-algorithmic)

### 0.2 学習する関係を具体化する

```text
最優先の関係A
レシピ + 材料 + センサー + 電気的特徴 + 装置履歴
    → 実際の加工結果とその不確かさ

最優先の関係B
運転条件 + 過去の観測 + チャンバー履歴
    → 未測定または将来の負荷・負荷遷移
    → PCDによる電圧、電流、反射、損失、素子ストレスの計算
```

後半の電気計算は既知の方程式を使う。学習は前半の未知関係を担当する。既に観測した同時刻のV/Iから同じR/Xを返すことや、PCDで生成した波形を同じ入力から再現することは、主目的にしない。

第2位の中でも、単に測定値を平滑化することと、未測定条件・履歴依存・着火後の遷移を予測することは効果が異なる。線形モデル、直前値保持、条件別lookup、RLS/Kalmanで十分ならMLを追加しない。動的モデルの適用範囲と観測可能性は別途確認し、履歴から任意の内部プラズマ状態を一意回収できるとは主張しない。

工程結果の予測をそのままレシピ変更の因果効果とみなさない。条件変更を提案する場合は、設計した実験、比較可能な条件、追加の実機検証により、その変更が結果へ与える効果を確認する。

### 0.3 優先度を下げる内容

| 内容 | 先に使う方法 | MLを再検討する例外条件 |
|---|---|---|
| 電圧・電流・反射・電力・ストレスの順計算 | PCDと解析式 | 大量反復や厳しい推論期限で、学習と再検証込みの利益が出る |
| 観測済みV/IからのR/X計算 | 校正と複素数の直接計算 | 欠測を他センサーから補うなど、別の情報が必要 |
| 少数RLCの同定、同定初期値 | 既存 `identify`、有界推定、多始点探索 | 多数の同種逆問題を繰返し、初期化の総費用削減を実証できる |
| 固定寄生・一定のモデル誤差補正 | 校正、固定値、簡単な回帰 | 条件や履歴に応じた未説明の誤差が残る |
| 単純なドリフト・異常検知 | RLS、Kalman、EWMA、残差管理図 | 複数信号・非線形性・履歴が追加の予測情報を持つ |
| 回路パラメータの測定条件選択 | 感度、Fisher情報、通常DOE | 実機応答の未知関係や複雑な履歴を学ぶ必要がある |
| 3種など少数の既知トポロジー比較 | 全種類を直接評価し、構造ごとに最適化 | 構造数・仕様反復が増え、学習した探索順の利益が出る |
| 任意トポロジー生成、PINN、FNO | 制約付き探索、既存数値解法 | 対象空間・データ・総費用で明確な優位性を示せる |

大きな構造空間の反復探索では、1計算が安くても総候補数が膨大になるため学習が有効になり得る。ただし、現在の3テンプレート比較にその価値を当てはめない。任意トポロジーを生成できること自体も、電気的性能や実用価値の証明ではない。

### 0.4 導入する効果の確認

「回路計算では解けない」だけでは、MLが簡単な統計手法より有利という証拠にはならない。次の比較で追加効果を確認する。

比較は「回路計算と既知の工程モデル」「それらに簡単な統計推定を追加」「同じ入力へ候補学習器を追加」の順で行う。回路だけでは予測対象を定義できない工程品質には、既存工程モデルまたは条件別平均を最初の基準にする。さらにfeatureを電気量のみ、工程条件追加、履歴追加へ段階的に増やし、どの情報が改善をもたらしたかを確認する。

| 目的 | 比較相手 | 採用を判断する改善 |
|---|---|---|
| 工程品質予測 | 条件別平均、線形回帰、PLS、工程別既存モデル | 将来run・PM・別条件での誤差低下、許容誤差内率、計測削減 |
| 未測定負荷予測 | 直前値保持、lookup、単純な状態モデル | 未測定条件・先の時刻での予測誤差と、回路判断の改善 |
| 異常・劣化予測 | 管理図、PCA、残差監視 | 同じ誤警報数での早期検出、同じ検出率での誤警報低下 |
| 計測・実験削減 | 固定sampling、通常DOE | 同じ品質判断・予測誤差を保つために必要な実測数の低下 |

学習後の誤差・警報改善・実測削減・運用費用を併記する。現状の本PCDについて、これらの改善率を数値で示す実測検証はないため、上の順位は期待効果と文献根拠に基づくものである。

`pcd.api` は現行major内で安定させる拡張面である。新パッケージからの計算呼出しはここへ限定する。保存成果物の取込みは公開ファイルスキーマに従う専用アダプターへ集約する。現状、安定した学習用データexport APIは提供されていない。

現行の最適化接続は小さなplugin契約であり、別の最適化パッケージを既に製品APIとして配布しているという意味ではない。新パッケージの責務は学習モデルの管理と提案であり、探索アルゴリズムや受容判定を複製しない。

`design`、`latent`、`control`、`operating`、`fixed`、`calibration` は別の役割である。現行探索が提案するのは、一度に `design` または `latent` の一役だけである。レシピ、装置構造、チューナ設定、未知負荷をまとめて一つの未定義ベクトルにしない。

### 1.2 トポロジーの現状

公開RF入力の接続テンプレートは `l_match`、`pi_match`、`pi_match_harmonic` の3種である。[トポロジーカタログ](../../pcd/topology_catalog.py)は接続と素子の役割を持ち、値・損失・周波数・制約はケースが持つ。

高度な入力では、[pcd/netlist.py](../../pcd/netlist.py)の `builder_variable` または `$param` により、登録済みbuilderをカテゴリ変数として選べる。一方、可変長の任意グラフ生成、グラフの正規化、GNN用の意味的グラフAPIは現行契約にない。`Circuit.raw` のSPICE記述には結合・制御源・behavioral要素も含められるため、二端子素子だけを抜き出したグラフでは情報が欠ける。

built-in `differential_evolution` は複数の `choices` を拒否する。builderのカテゴリ探索にはgrid、random、またはカテゴリに対応するpluginを使い、構造内の連続値探索とは区別する。

[統合マニュアル](../manual-ja.md#development)と公開API・実装を、現在提供する機能の根拠とする。端子同定は既に実装されており、以下はその再利用と追加研究の採否を検討する。

## 2 問題の本質と機械学習の役割

### 2.1 電気的観測から推定できる量

端子の複素インピーダンスは周波数と基準面を伴って初めて意味を持つ。PCDの有効CCPモデルは

```text
Z(ω) = R_eff + jωL_eff + 1/(jωC_eq)
```

であり、単一周波数の複素観測は2つの実数情報しかない。3つの未知量を同時に自由同定するには情報が不足する。大量の合成データで逆ニューラルネットを学習しても、この欠落は埋まらない。学習器が一つの値を返す場合、それは訓練分布や事前仮定が選んだ値である可能性がある。

ICPも端子で識別できる反射負荷の組合せを推定対象にする。`gamma_secondary` を衝突周波数とみなすには、独立したプラズマ計測や仮定が必要である。[現行の物理境界](../manual-ja.md#loads)に従い、有効値と物理状態のラベルを区別する。

同定の改善では、まず複数周波数、同期したV/I、別の観測点、plasma-off/on、dummy/fixture測定など、独立した情報を追加する。その後にノイズを考慮した推定、事前分布、学習による初期化を比較する。

### 2.2 準静的な負荷と動的なプラズマ

現行 `impedance_profile` は時刻順の独立AC条件である。時間順になっていても、状態伝搬、ヒステリシス、蓄積エネルギー、プラズマへの電力フィードバック、アクチュエータ運動を解いていない。[準静的モデルの契約](../manual-ja.md#loads)を、動的状態推定の教師データと混同しない。

パルス、着火、消滅、モード遷移を扱うときは、履歴と状態更新を含む別モデルが必要になる。時間変化する容量・インダクタンスを扱う場合も、`q=C(t)v`、`φ=L(t)i` に従ったcharge/fluxの時間微分と外部エネルギー交換を定義する必要がある。現行の[動的検証例](../studies/etch-ccp-dcs-dynamic-impedance-study-ja.md)は、この法則を明示したケース固有の既知真値検証であり、自己整合な放電モデルではない。

複数RF源やICPとCCPの併用では、各portの基準面、同期、相互結合を区別する。現行の汎用RF負荷は一端子表現であり、独立した一端子の結果を足しただけでは結合系の電力分配は決まらない。結合を学習するなら、相関した観測と明示した多port・状態モデルを別途定義する。

### 2.3 半導体製造で必要になる追加情報

反射電力や有効負荷の予測が正しくても、etch rate、選択比、面内均一性、損傷、歩留まりの予測が正しいとは限らない。これらにはガス、圧力、温度、表面、レシピ履歴、チャンバー状態と実際の計測ラベルが必要である。回路出力から電子・イオンへの分配電力や化学種を自動的に教師ラベル化しない。

従って新パッケージは、回路専用の学習器に限定せず、実測電気量、プロセスセンサー、OESなどのスペクトル、製品計測を対応付けられる設計にする。ただし、初期段階から全センサーを必須にする必要はなく、用途ごとに必要な観測を明示する。

### 2.4 プラズマと製造用途の研究が示す範囲

| 一次研究 | 実証または報告された内容 | 本設計への含意と限界 |
|---|---|---|
| [V/Iの同時校正](https://arxiv.org/abs/2212.13047)、2022 | 容量性のAPPJで、90度近傍の位相誤差が吸収電力評価へ大きく影響する問題を校正で扱う | 校正をMLの自由補正へ隠さない。高電力CCP/ICP全体での保証ではない |
| [外部回路とプラズマの連成](https://cpseg.eecs.umich.edu/pub/articles/jap_83_5087_1998.pdf)、1998 | 基本波で同等なTとπ回路でも、高調波とDC biasを通じてプラズマ特性が変わりうることを示す | 基本波のR/Xだけで工程の同等性を判断しない。非線形sheathと外部回路の条件を確認する |
| [CCPの適応モデルと制御](https://www.sciencedirect.com/science/article/pii/S0098135418309633)、2019 | ArのCCPで逐次モデル推定を使い、人工的なdrift下の密度制御を評価する | RLSや状態推定を基準手法に含める。製造レシピ全般や未知の故障に対する実証ではない |
| [plasma etchの仮想計測](https://mural.maynoothuniversity.ie/id/eprint/3560/1/JR_Global.pdf)、2012 | 工業用チャンバーの工程センサーと電気的観測からetch rateを推定し、windowed GPRを評価。global modelの時刻順評価ではPLSが良い入力構成もある | 実測センサーと製品計測がMLの入口になる。手法順位は入力・分割に依存し、別chamber・新chemistryへの一般化を証明したものではない |
| [online GPによる動的計測](https://www.nist.gov/publications/comparative-study-semiconductor-virtual-metrology-methods-and-novel-algorithmic)、2025 | CMPの公開実データに設けた三つの模擬drift/shiftシナリオで、適応と計測samplingを評価する | 計測削減を目的にする参考になる。実fabでのsampling便益、プラズマetch・RF負荷への直接実証ではない |
| [etchのheteroscedastic GP](https://arxiv.org/html/2511.04990v1)、2025年11月preprint | ICP-RIEの84条件と各wafer9位置を使い、膜厚の平均と条件依存分散を扱う。85/15のrandom splitを10回行う | 不確かさを扱う有望な事例。ただし新装置・PM・時間drift・OOD・提案最適条件の追加実験は未確認。位置間分散とwafer間変動を分ける |

これらからの設計判断は、巨大な回路surrogateの選定より、計測条件・校正・group・ラベル定義・更新方策が先に必要ということである。いずれの研究も本PCDの新パッケージを検証したものではない。

## 3 追加効果に応じた技術選択

以下は導入候補である。各用途でまず簡単な基準手法を作り、実際の利用条件で追加価値を確認する。

| 用途 | 入力と目的 | 先に比較する手法 | 学習技術の候補 | 優先度と条件 |
|---|---|---|---|---|
| 仮想計測と工程応答 | センサー・レシピ・回路特徴・材料から製品計測を予測 | Ridge/PLS、条件別平均、加法モデル | GP、勾配boosting、必要ならスペクトル・系列モデル | 最優先。製品計測ラベルが必須 |
| 未測定負荷と履歴依存挙動 | 運転条件・別センサー・過去履歴から将来または未測定条件の負荷を予測 | lookup、直前値保持、単純な状態モデル | 小規模GP、boosting、学習した状態遷移・残差 | 最優先。単純モデルに対する予測改善を確認する |
| 多センサーによる早期異常・劣化予測 | 正常条件差と履歴を考慮して将来の悪化を予測 | 管理図、PCA、残差監視、状態空間モデル | 条件付き正常モデル、分類器、必要なら系列モデル | 条件付き高。単純な閾値・追従だけなら低 |
| 学習した実機応答による計測選択 | 高価な製品計測・実験をどこに配分するか | 固定sampling、通常DOE | 上位モデルの予測と校正済み不確かさを利用 | 条件付き高。独立の初期学習taskにはしない |
| 条件依存の実機補正 | 校正後にも残る実測と計算の差を予測 | 固定補正、線形回帰、条件別同定 | GP、加法モデル、boosting | 中。一定の寄生補正なら低 |
| 繰返し同定の初期化 | 観測から複数の有効パラメータ候補を返す | 現行 `identify`、有界最小二乗、多始点探索 | 小回帰器、条件付き分布推定 | 低。大規模反復で費用削減が出る場合のみ再検討 |
| 回路パラメータの測定条件 | どの周波数・励振・観測点が未知量を区別するか | 感度行列とノイズを用いた実験計画 | 必要ならBayesian実験計画 | ML優先度は低。通常の計算で可能 |
| 既知回路群の選択と探索初期化 | 負荷・要求仕様から有望なbuilderや素子値を選ぶ | 各テンプレートの直接探索 | tabular ranker、候補分布モデル | 少数種類では低。大きな構造空間と反復利用時のみ再検討 |
| 新しい回路構造の探索 | 許可された素子・接続から構造を生成 | 制約付き列挙、graph grammar、既存の数値最適化 | GNNによる順位付け、制約付き生成、必要ならRL | 現時点では低。規模・データ・利益の確認が先 |
| 順計算の高速近似 | 既知回路から波形・電気指標を予測 | 直接PCD計算、条件に応じた解析式 | 小規模surrogate、縮約波形モデル | 低。総時間または推論期限で利益を実証した場合 |

同じ周波数・基準面で同期したV/Iが既に得られているなら、R/Xは `Z=V/I` から直接求められる。ここに学習器を必須にしない。MLの負荷予測では、そのV/Iを教師・検証観測にし、予測時点で利用できる別情報から未測定条件や将来を予測する。電流が小さい領域の誤差増幅と校正ノイズも区別して扱う。

### 3.1 小規模の表形式データ

GPは少数の連続条件から滑らかな応答とモデルに基づく分散を得たい場合に適する。Matérnなどのkernelと観測ノイズを明示する。scikit-learnの実装はdenseで、高次元・大量データでは費用が増えるため、全波形サンプルをそのままGPへ投入しない。[GP公式仕様](https://scikit-learn.org/stable/modules/gaussian_process.html)

解釈が必要な場合は、各変数のスプラインとRidgeを組み合わせた加法モデルから始められる。相互作用や条件差が強く、十分な表形式データがあれば `HistGradientBoostingRegressor` を比較する。公式実装はカテゴリ、欠損、quantile loss、単調性・相互作用制約に対応するが、確率区間の妥当性や外挿性能を自動的に保証しない。[boosting公式仕様](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html)

単調性制約は、その物理量と適用領域で根拠がある場合に限る。L/Cの値に対して反射や共振応答が全域で単調とは限らない。加法モデルの効果図やfeature importanceも、因果効果や逆問題の識別可能性の証明ではない。

### 3.2 実測と計算の差を学習する

負荷補正を採用する場合は、自由な波形補正より、許可された電気パラメータを条件依存で補正する方式を優先する。この方式の優先は負荷予測task内の判断であり、工程品質の仮想計測より先に実装するという意味ではない。

```text
θ_eff = bounded_transform(h(context))
y_pred = PCD(case, θ_eff)

必要な場合:
y_measured = y_pred + δ(context, observation_axis) + measurement_noise
```

`θ_eff` のboundsや正値性を守る構成は、自由なR/X補正より物理的な検証をしやすい。ただしこれでモデル族に存在しない物理が表現できるわけではない。自由残差を追加すると、パラメータ変化とモデル誤差が互いを説明してしまうため、独立校正値の固定、残差の制限、別条件での検証を行う。この区別は統計的なモデル校正で重要である。[KennedyとO'Haganのモデル校正研究](https://rss.onlinelibrary.wiley.com/doi/abs/10.1111/1467-9868.00294)

受動な定常一端子の指定周波数で `Re(Z)>=0` を守ることと、周波数全体で因果性・受動性を守ることは別の条件である。RとXを独立回帰して周波数外へ補間・外挿する場合は、後者の検証が必要になる。実測の負のRを無条件に切り捨てる処理も避け、元データと品質フラグを保持する。

### 3.3 逆推定と不確かさ

少数パラメータで計算が安ければ、有界のrobust least squaresと多始点探索が有力な基準手法になる。複素残差は実部・虚部を並べ、観測ノイズ共分散とパラメータの尺度を考慮する。SciPyはbounds、robust loss、Jacobianを提供するが、大域一意性を保証するものではない。[SciPyの最小二乗仕様](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)

学習による逆写像は、複数候補を返して既存探索で補正する用途から始める。パラメータRMSEだけでなく、補正後の観測一致、未使用条件、電気的制約、総時間で評価する。多峰の事後分布が必要で、観測尤度が扱いにくく、同じ問題族で繰返し推定する場合は `sbi` のneural posterior estimationを候補にする。既知のノイズ尤度と低コスト計算があるなら、直接Bayesian推定も比較対象になる。[sbi公式資料](https://sbi.readthedocs.io/en/latest/)

GPの標準偏差、Bayesian事後分布、quantile予測、conformal予測区間を一つの `confidence` 値へまとめない。conformal法の保証にはデータの交換可能性が必要で、同じrunやchamber内の相関した行を普通の独立標本として扱えない。group分割だけで保証が成立するとも限らない。[階層データの予測集合研究](https://arxiv.org/abs/1809.07441)

周波数点ごとの95%区間と、全sweepを同時に覆う95%帯も別である。全曲線の保証が必要なら、sweep単位の最大正規化残差などを用いた校正と被覆評価を設計し、その場合も交換可能性の単位と対象分布を明示する。

### 3.4 計算が安いことを実験計画に使う

候補測定条件 `d` について、観測の感度 `J(d)` とノイズ共分散 `Σ(d)` を計算し、局所情報行列を比較する。

```text
F(d) = J(d)^T Σ(d)^(-1) J(d)
```

実装ではノイズで残差をwhitenし、パラメータを尺度化して比較する。D-optimalやA-optimalなどの基準を使う場合も、局所近似・事前分布・観測ノイズの仮定を記録する。rank不足の方向を無視した行列式や逆行列は使わない。校正パラメータなどのnuisance uncertaintyも必要に応じて含める。

MLの予測分散が最大の点を選ぶことは、未知電気パラメータを最も区別できる条件を選ぶことと同じではない。非線形性や多峰性が強い場合にexpected information gainなどへ進む。事前分布やノイズモデルの誤設定に頑健な実験計画も研究されているが、本装置での有効性は検証が必要である。[Robust A-optimal design](https://arxiv.org/abs/2305.03855)

頻繁に適応的な実験を行い、毎回の設計計算が推論期限を超える場合に、事前学習した実験方策の価値が生じる。[Deep Adaptive Design](https://proceedings.mlr.press/v139/foster21a.html)はこの学習費用の反復利用を扱う。初期段階の少数測定では通常の実験計画を先に比較する。

### 3.5 時系列と異常

状態推定の設計案は、低速の潜在状態とRF観測を分ける構成である。

```text
state[k+1] = g(state[k], recipe[k], actuator[k], dt[k]) + process_noise
observation[k] = h(state[k], excitation[k], fixture) + measurement_noise
```

EKF/UKFなどは統計的な基準手法であり、ニューラルネットではない。既知の状態遷移・観測式で十分か確認し、学習器は遷移や観測の残差を補うところから導入する。波形のcarrier周期、pulse内の状態、wafer間・PM間のドリフトを同じ時刻尺度へ潰さない。TCN/GRUは因果的な履歴が追加情報を持つと確認した場合の候補である。

異常検知は原因診断と分ける。モデル残差の増加だけでは、プラズマ変化、センサー故障、基準面のずれ、未学習レシピを区別できない。通知の評価には正常run当たりの誤警報、検出遅延、未検出、既知原因ラベルが必要になる。

### 3.6 高度な学習器を初期標準にしない理由

PINNは物理式があることだけでは直接数値解法より優位にならず、soft constraintの学習にもconditioningや最適化の失敗がある。[PINNの失敗モード研究](https://proceedings.neurips.cc/paper_files/paper/2021/hash/df438e5206f31600e6ae4af72f2725f1-Abstract.html)を踏まえ、最初は既存solver、パラメータbounds、明示した状態法則を使う。

FNOなどのneural operatorは、関数から関数への写像や空間分布の反復計算が目的になったときに再検討する。小規模な有限次元回路や数個の電気指標だけが対象なら導入根拠が弱い。[FNOの原論文](https://arxiv.org/abs/2010.08895)はPDE operatorを対象とする。巨大Transformer、拡散モデル、RLも、必要なデータと反復利用の利益を確認してから選ぶ。

## 4 トポロジーを扱う場合の設計

### 4.1 三つの異なる問題

| 問題 | 正しい目的 | 注意点 |
|---|---|---|
| 既知のmatching network選択 | 要求条件に対してどのbuilderが有望か | 3テンプレートなら全種類の直接探索が強い基準になる |
| プラズマの等価回路モデル選択 | 観測を説明できる最小のモデル族は何か | 当てはまりだけで内部構造の真実と判断しない。未使用周波数・条件と識別可能性を確認する |
| 新しいnetwork synthesis | 制約内で接続と素子数を変えて要求を満たすか | 可変構造の表現、合法な生成、探索、数値最適化、実solver検証が必要 |

### 4.2 新規構造探索の基準構成

```text
許可した素子と接続規則
    → 制約付き生成または有限列挙
    → 接続検証と重複排除
    → 構造ごとの素子値最適化
    → 全宣言条件でPCD評価
    → 制約、素子数、損失、可調整性を比較
```

先にこの経路を作り、候補数が十分に大きくなったときに、構造特徴やGNNで評価順を改善する。rankingだけで候補を除外すると有望構造を落とす可能性があるため、探索用の未選択候補も評価する。探索済み候補のPareto frontを全構造空間のfrontとみなさない。

GNNの構造識別力には限界があるため、グラフ表現を導入しただけで精度が解決するとは言えない。[GNNの識別力の研究](https://arxiv.org/abs/1810.00826)は、この限界を一般グラフ上で示している。RF回路での誤差・成功率は別途検証する。

2026年の[AnalogToBi](https://arxiv.org/abs/2603.08720)は二部グラフ表現、名前変更のaugmentation、grammarに従う生成を扱う。[AstRL](https://arxiv.org/abs/2602.12402)はトランジスタ単位の構造生成とsimulator feedbackを扱う。いずれもアナログICの研究報告であり、プラズマ用RF matchingの性能を実証したものではない。参照する価値は、表現・接続制約・実solver検証の構成にある。

### 4.3 グラフ契約を先に定義する

将来の `CircuitGraphSpec` は、netとdeviceを分けた二部グラフまたはpin incidence表現を候補にする。port、接地、端子の順序、極性、素子種類、値と単位、結合関係、制御源、subcircuit、behavioral lawを持つ。初期対応を受動RLCなどの明示した素子集合に限定し、未対応のraw SPICEを黙って近似変換しない。

net名や素子名の付け替えは同じグループへまとめる。graph isomorphismと電気的等価性は別であり、有限の測定周波数で応答が似ただけで全周波数・非線形・過渡まで同値としない。train/testは、同名変更、同構造の素子値違い、同じ生成元の近傍候補を考慮して分割する。

トポロジー学習の評価は、構文上の合法率、solver成功率、top-kでの実行可能候補回収率、最適化後の制約充足、直接探索に対する目的値の差、全費用を測る。生成netlistの見た目や平均予測誤差だけで判断しない。

## 5 データ形式と標本の単位

本節は、高度なデータを扱う場合の参考契約であり、初期パッケージの必須仕様ではない。初期は既存の一つの表または数値配列から入力列と目的列を選ぶだけとし、[詳細調査の第6節・最小入出力仕様](high-value-learning-methods-survey-ja.md)に従う。

### 5.1 現行成果物をどう読むか

| 現行データ | 粒度 | 学習への変換 |
|---|---|---|
| `evaluations.csv` | Candidate × Scenario × Controlの1評価行 | 役割付きパラメータ、全status、指標、制約margin、raw identityを保つ |
| `study_history.json` | 1候補の集約履歴 | 探索の追跡に使用し、独立実験数として数えない |
| `data/ac.csv` | 1solve内の周波数別phasor | 周波数・複素実部虚部・基準面・単位とphasor規約を保持する |
| `data/transient.csv` | 1solve内の時刻別サンプル | 系列全体をgroupとし、元波形・観測点・時刻を保持する |
| `snapshot_response.csv` | 選択候補の準静的時刻別投影 | 各点が独立ACであることを記録する |
| 同定用のV/I観測表 | fit/holdout条件別の複素観測 | 実測identity、校正、ノイズ、繰返しの情報を加える |

AC標準列は `frequency_Hz, voltage_re, voltage_im, current_re, current_im` である。列名だけから単位を自動推測しない。[pcd/ngspice_io.py](../../pcd/ngspice_io.py)のschemaに対応する辞書を作る。ACはpeak phasorで、`P=0.5 Re(V conj(I))`、`RMS=|phasor|/sqrt(2)` である。source currentとdelivered currentの符号を区別し、同定用観測はdelivered符号で扱う。[AC解析](../../pcd/analysis/ac.py)、[同定用入力](../manual-ja.md#identification)

`selected_control`、選択フラグ、最終指標は目的によりラベルになる。これらを同じ最適制御を予測する特徴量へ入れない。best/Pareto行だけで学習すると、探索で残った領域へ分布が偏る。全評価行を保持し、サンプリング方策も記録する。

raw cache hitや同じ物理入力の再評価は、新しい独立観測ではない。simulationの重複はraw keyとhashで識別する。実測のrepeatは消さず、測定run IDとrepeat IDで区別する。generationの `dataset_id` は成果物の識別子であり、waferやchamberの独立性を保証しない。

### 5.2 高度なデータを扱う場合の参考スキーマ

以下は、高度なデータを扱う必要が生じた場合の `pcd.learning.dataset.v1` の参考案である。表形式のviewと、可変長の配列・波形のviewを同じmanifestに結び付ける。JSON manifest、CSV表、NPZ数値配列などを利用できるが、初期の一表入力にこれらをすべて要求しない。大規模データになったらParquetなどを検討する。

| レコード | 必要な情報 |
|---|---|
| `DatasetManifest` | schema、全ファイルhash、出典、物理モデル、生成・測定条件、data identity |
| `Observation` | observation ID、source kind、観測点、周波数または時刻軸、複素数の実部虚部、SI単位、valid mask |
| `Context` | chamber、recipe、lot、wafer、run、session、PM区間、測定日時、必要なプロセス条件 |
| `MeasurementSpec` | instrument、基準面、校正ID、de-embedding、電流符号、peak/RMS、ノイズ共分散または未知の明示 |
| `ParameterSpec` | 名前、役割、単位、bounds、scale、固定根拠、モデル族 |
| `FeatureSpec` | 順序、変換、利用可能時刻、欠損処理、特徴抽出version |
| `TargetSpec` | 電気量・状態・製品計測の別、定義、単位、label source、観測誤差 |
| `SplitSpec` | train/validation/interval calibration/testのID、group key、時刻境界、予測する対象集団 |
| `ModelArtifact` | 学習器、設定、依存version、訓練hash、split hash、適用範囲、校正・検証証拠 |
| `Prediction` | 点予測または候補分布、区間の意味、適用範囲status、棄却理由、モデルID |

`source_kind` は少なくとも `measurement` と `simulation` を区別する。独立基準としての役割は別の `reference_role` とprovenanceへ記録する。独立solverのsimulationも独立実測も基準になり得るため、由来と検証上の役割を同じenumに混ぜない。合成データの既知パラメータは実機truthへ昇格させない。ノイズ量や校正記録が不明なら、既知として数値を埋めない。

実測の詳細な記録を残す場合のCSV例は次の列構成である。これはPCDや初期学習パッケージの必須列ではない。

```text
observation_id,run_id,chamber_id,recipe_id,repeat_id,timestamp_utc,
frequency_Hz,resistance_ohm,reactance_ohm,reference_plane,instrument_calibration_id
```

waveformは `run_id, pulse_id, time_s` と同期したV/I・観測点を保持する。製品計測は別表に `wafer_id, site_id, metrology_time, target, unit` を持ち、runへの対応と予測時点を明示する。wafer内の複数位置の分散、wafer間の繰返し変動、計器ノイズを同じ量とみなさない。

### 5.3 有効性と失敗

solver成功、計測成立、電気的制約充足、実機予測の妥当性は別々に記録する。`failed`、`not_settled`、`invalid` の目的値を0で埋めない。数値targetにはmaskを付け、原因とfailureラベルを残す。failureを予測するモデルを作る場合も、solver失敗と装置の不良を別ラベルにする。

PCDの制約marginは物理値として保持する。制約境界近傍では、平均誤差が小さくても誤受容が起こりうる。MLによる電気的候補の採用は、最終的にPCDの再計算と全宣言条件の評価へ戻す。製造品質についてはさらに実測検証が必要である。

## 6 別パッケージの最小コード設計

### 6.1 配布と扱う範囲

配布名を仮に `pcd-learning`、import名を `pcd_learning` とする。PCDの配布に学習依存を加えず、別パッケージとして利用できる形にする。

**既存の一つの表または数値配列から、利用者が入力列 `X` と目的列 `y` を選ぶ。** 目的列は最初に一つ指定する。加工結果、実測負荷、その他の数値応答を同じ回帰操作で扱い、用途ごとの専用frameworkを設けない。入力・目的を明示することと、学習器を共通にすることは両立する。

初期の処理は `fit → evaluate → predict → save/load` で足りる。入力は利用者が既に持つ列を使う。追加センサー、製品・保全データの収集、複数表の結合、自動特徴抽出、時系列や異常検知の専用taskを初期の前提にしない。

### 6.2 小さなモジュール構成

```text
src/pcd_learning/
  api.py             # fit、predict、evaluate、save、load
  data.py            # 表・配列からX/yを選択、列順と数値の確認
  models.py          # Ridge基準、必要なGPまたはboosting
  evaluation.py      # 同じ入力・分割で誤差を比較
  artifacts.py       # モデル、列指定、前処理、評価の保存
  pcd_adapter.py     # 必要な場合だけPCD公開APIに接続
```

NumPyとscikit-learnを中心に始める。Ridge等の簡単な回帰を基準にし、滑らかな少数変数の関係にはGP、非線形な相互作用にはboostingを比較する。すべての学習器を必ず実装・実行する必要はない。

PCD接続は任意とする。予測した負荷を電気応答や制約の計算へ渡す場合にだけ `pcd.api` を呼ぶ。既にPCDで安く求められる電圧・電流・反射等を学習で置き換えることは低優先のままとする。

### 6.3 利用操作の例

以下は設計案であり、現行の実行可能APIではない。`table` と `test_table` は利用者が用意した既存の表、列名も説明用の例である。

```python
model = fit(
    table,
    input_columns=["condition_a", "condition_b"],
    target_column="measured_response",
    method="ridge",
)
report = evaluate(model, test_table)
prediction = predict(model, new_table)
save(model, "model_directory")
model = load("model_directory")
```

配列では `X[N, F]` と `y[N]` を渡す入口も用意できる。列の順序、前処理、目的の定義をモデルと一緒に保存し、再読込み後も同じ意味で予測できるようにする。入力に無い情報を勝手に補い、目的列や結果から得た列を入力へ混ぜない。

train/testは同じ入力列で比較する。時刻やrun等のgroup列が既にある場合は、予測目的に合わせて時間順またはgroup別に分割する。それらの列や管理データを新たに集めることは必須にしない。前処理はtrainだけで学習し、testを学習・モデル選択へ使わない。

### 6.4 改良の単位

最初は一つの目的列について、簡単な回帰から追加効果が出るかを確認する。改善が必要な箇所に限り学習器を交換し、同じ入力と評価条件で比較する。保存したモデルと評価を残せば、結果を確認しながら継続して改良できる。

不確かさ、履歴特徴、系列モデル、測定選択は、現在の表と最小モデルで不足が確認された場合にだけ検討する。調査済み技術をすべてパッケージの責務にする必要はない。

## 7 精度と価値の検証

### 7.1 利用目的に対応した分割

| 実際の予測対象 | testの切り方 |
|---|---|
| 同じ装置の次のrun | 時刻を前へ進め、過去だけで学習する |
| 新しいレシピ | recipeまたはrecipe familyを丸ごと外す |
| 別chamberやPM後 | chamber、session、PM区間を外す |
| 新しい回路構造 | portとdeviceの役割を含む構造groupを外す |
| 未観測の周波数や励振 | sweep全体や連続した条件領域を外す |

一つの波形の時刻行、同じsweepの周波数行、同じwaferの位置をランダムに分けた精度は、別run・別waferへの性能の根拠にならない。前処理、feature選択、hyperparameter調整、区間校正はtestを使わず行う。[scikit-learnの検証仕様](https://scikit-learn.org/stable/modules/cross_validation.html)を基に、groupとtimeを同時に満たすsplitを保存する。

予測区間を追加する場合は、校正用データを訓練・モデル選択・最終testから区別する。区間は、新しいgroupへの予測なのか、既知group内の繰返しなのかを明示する。ドリフトやOODで同じ被覆保証が続くとはみなさない。

### 7.2 比較する指標

| 用途 | 必要な評価 |
|---|---|
| 複素負荷と補正 | R/Xの単位付き誤差、ノイズ尺度に対する誤差、周波数別worst error、共振・制約近傍 |
| 同定と初期化 | 未使用観測の誤差、パラメータ曖昧性、補正後の成功率、総時間 |
| 不確かさ | 独立groupでの被覆率、区間幅、誤受容、OODでの棄却と残存誤差 |
| 測定条件選択 | 同じ実験予算でのパラメータ不確かさ・予測誤差の低下 |
| 異常検知 | 正常run当たり誤警報、検出遅延、未検出、レシピ変更への頑健性 |
| 仮想計測 | wafer単位と位置別の誤差、実測ノイズ、PM・chamber・recipe別の性能 |
| トポロジー | top-k回収率、真solverでの実行可能率、最終目的値との差、探索の網羅範囲 |

許容誤差は測定誤差と工学上の要求から定める。本調査だけで「全用途1%以下」などの閾値は設定できない。平均値に加え、条件別の悪い領域と棄却した割合を示す。モデル選択は予測誤差だけでなく、これらの後段評価で行う。

### 7.3 低コスト計算との費用比較

現在の保存済み[動的CCP成果物](../../bench/figures/etch_ccp_dcs/figure_data.json)には、3 runの評価時間中央値が約0.858〜0.864秒、各200候補の評価時間合計が約150〜162秒と記録されている。これは当該ケースと保存環境の値であり、全PCDの性能値ではない。

この時間は [集計コード](../../bench/figures/etch_ccp_dcs_optuna_evidence.py)が `study_history.duration_s` を集計したものなので、cache hitを含み、学習・候補提案を含む探索全体のwall timeではない。[pcd/core/pipeline.py](../../pcd/core/pipeline.py)の評価範囲と [pcd/study.py](../../pcd/study.py)の集計を確認した。したがって、この値だけからsurrogateの速度向上率を計算しない。

導入前には次を同じ条件で測る。

```text
T_direct = 直接探索・同定を完了する総wall time
T_learning = データ生成 + 学習 + 再学習 + 推論・候補生成 + 真solver再検証
```

既存データを使う場合も、その生成費用を初期費用と再利用費用に分けて報告する。反復回数、solver実行数、cache、並列数、warm/coldの条件をそろえる。学習費用を多くの設計に分散できる場合、ms級のオンライン期限が必要な場合、実験を削減できる場合に価値が生じる。BO自体の費用が安い目的関数を上回りうることも研究上指摘されている。[低コスト関数のbatch BO研究](https://arxiv.org/abs/1811.01466)

反復する同種の要求数を `Q` とすると、速度を目的にする導入基準は次の形になる。

```text
T_create + T_train + T_retrain
  + Q * (T_predict + T_refine + T_verify)
  < Q * T_direct_per_request
```

1要求当たりの推論・精密化・再検証時間が直接処理時間以上なら、初期学習費用を反復利用しても速度では利益が出ない。その場合は、実機差の補正、計測削減、不確かさの提供など別の目的で価値を判断する。

合成ノイズのstress testは有用だが、実機検証とは別に報告する。PCD再検証が通っても、モデルに含まれない実機物理や製品品質を検証したことにはならない。

## 8 最初に実装する内容

### 8.1 一つの目的列で始める

初期リリースは、**既存の入力列と目的列を選び、回帰・比較評価・予測・保存を行う機能**に絞る。追加データの取得や結合を先行作業にせず、手元の表で扱える目的を一つ選ぶ。

工程品質の列があるならその予測、実測応答の列があるなら未測定条件での応答予測を候補にする。目的列が回路計算から安く得られる量であれば、直接計算を優先する。PCD合成データを使う場合も、実機での追加効果を確認したことにはしない。

実装する操作は `fit / predict / evaluate / save / load`、学習器はRidge等の簡単な基準と必要なGPまたはboostingに限る。まずは一つの表と一つの目的列で完結させる。

### 8.2 改善の確認と必要な拡張

同じ入力列と同じ未使用データで、単純回帰に対する誤差の改善を確認する。時刻やgroup列が既にある場合は適切な分割に使う。必要な検証は、入力列の順序、目的列の混入防止、trainだけでの前処理、保存・読込み後の予測再現、基準手法との比較である。

PCD adapterを使う場合には、予測する電気量の単位と基準を確認し、PCD公開APIによる再計算へ渡す。工程品質や実機応答の有効性は本調査では未検証であり、PCDの計算が通ることと区別する。

最小構成で有用性を確認した後、不足する内容だけを追加する。履歴、異常予測、測定選択、構造探索などは初期必須にしない。通常の回路計算、同定、少数トポロジー比較は既存基盤を使い続ける。
